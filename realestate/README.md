# 도쿄 7구 대규모 맨션 가격추이

千代田・中央・港・新宿・文京・江東・渋谷 **7개 구**, **총 500세대 이상**(화면에서 200/300/500 전환 가능) 맨션의
**중고 호가**·**신축 분양가**·**신규 매물**을 구별·분기별 **坪単価 중앙값**으로 추적하는 사이트.

```
realestate/
├── config.json          수집 조건 (대상 구, 세대수 하한, 소스별 접근 설정)
├── build_standalone.py  단일 HTML 파일로 묶기 (공유용)
├── data/incoming/       손으로 넣는 CSV 자리 (템플릿 포함)
├── collector/           수집 파이프라인 (Python 3.11, 표준 라이브러리만)
│   ├── schema.py        포털별 제각각인 필드를 Listing 하나로 정규화
│   ├── sources/         데이터 소스 어댑터 (포털 4 + 라이선스 피드 + 샘플)
│   ├── store.py         스냅샷 저장 · 일별 차분 · 관측 로그
│   ├── market.py        가격추이 집계 (자체 수집 + 국토교통성 공식 API)
│   └── run.py           실행기
└── web/                 정적 사이트 (의존성 없음, GitHub Pages 그대로 배포)
    ├── index.html · app.js · styles.css   (한국어/일본어 전환 내장)
    └── data/            수집기가 생성하는 JSON
```

## 실행

```bash
python3 -m realestate.collector.run --config realestate/config.json
cd realestate/web && python3 -m http.server 8000     # http://localhost:8000
```

매일 09:10 JST에 `.github/workflows/realestate-daily.yml` 이 같은 명령을 돌리고
결과 JSON을 커밋합니다.

## ⚠ 먼저 알아야 할 것 — 데이터 출처 문제

**지금 사이트에 보이는 숫자는 전부 가상 데이터입니다.** 실제 도쿄 시세가 아닙니다.
페이지 상단에 경고 배너가 떠 있고, 실제 소스를 연결하면 자동으로 사라집니다.

이유는 단순합니다. SUUMO·LIFULL HOME'S·at home·不動産ジャパン **어느 곳도
제3자에게 물건 목록을 공개 API로 주지 않고**, 이용약관은 자동수집을 금지합니다.
그래서 이 저장소에는 크롤러가 들어 있지 않습니다. 대신 정당한 접근 경로를
확보했을 때 그것을 꽂는 자리를 만들어 두었습니다.

### 세 가지 가격 계열과, 각각의 현실적인 조달 경로

| 계열 | 이 사이트에서의 위치 | 합법적인 조달 경로 |
|---|---|---|
| **중고 호가** | 메인 추이 (200세대 필터 적용) | 宅建業免許 + REINS(ATBB) / 포털 掲載企業 계약 / 데이터 벤더 |
| **신축 분양가** | 메인 추이 파선 | 不動産経済研究所·東京カンテイ 등 상용 데이터. 무료 공개 시계열은 없음 |
| **신규 매물** | 신규 매물 섹션 + 추이에 편입 | 위와 동일 (매일 수집분의 차분) |
| *(참고)* **성약가** | 하단 참고 차트 | **국토교통성 不動産情報ライブラリ — 무료·공식** |

### 세대수 필터의 중요한 한계

국토교통성 성약가 데이터에는 **총세대수도 물건명도 없습니다.** 따라서
"500세대 이상만"을 그 데이터에 적용할 수 없습니다. 공식 성약가 차트는
구 전체 수치이며, 사이트에도 그렇게 표기됩니다.

세대수 필터가 걸린 추이는 **총세대수가 함께 오는 매물 데이터**(포털/피드)에서만
나옵니다. 그리고 과거 매물 데이터는 소급해서 살 수 없으므로, **실제 소스를
연결한 날부터 축적되는 만큼만** 추이가 그려집니다.

## 실제 데이터 연결하기

### 1. 국토교통성 공식 성약가 (무료, 지금 바로 가능)

<https://www.reinfolib.mlit.go.jp/> 에서 API 키를 발급받아 환경변수로 넣습니다.

```bash
export REINFOLIB_API_KEY="발급받은_키"
python3 -m realestate.collector.run
```

GitHub Actions에서는 저장소 Secrets에 `REINFOLIB_API_KEY` 로 등록하면 됩니다.

### 2. 포털 / 라이선스 피드

`config.json` 의 해당 소스에 접근 방식을 적습니다. `basis`(이용 근거)를 비워 두면
어댑터가 실행을 거부합니다 — 출처 불명 데이터가 조용히 섞이지 않게 하려는 장치입니다.

```jsonc
"suumo": {
  "enabled": true,
  "access_mode": "feed",              // "api" 또는 "feed"
  "basis": "○○不動産 掲載企業契約 2026-03",
  "location": "data/incoming/suumo.csv",
  "format": "csv",
  "encoding": "cp932",                // 업계 CSV는 Shift_JIS가 흔함
  "field_map": { "総戸数": "...", ... }
}
```

`access_mode: "api"` 면 `endpoint` + `api_key_env` + `json_path` + `field_map` 을 채웁니다.
어느 쪽이든 `total_units`(総戸数)를 매핑해야 세대수 필터가 동작합니다.
`sub_area`(가장 가까운 역 이름)를 매핑하면 역세권 지도·추이에도 잡힙니다.

연결이 끝나면 `sources.sample.enabled` 를 `false` 로 바꾸세요.

## 동작 방식

1. **수집** — 활성화된 소스에서 매물을 가져옵니다. 건너뛴 소스는 사유와 함께 사이트 하단 "데이터 출처"에 표시됩니다.
2. **중복 제거** — 같은 물건이 여러 포털에 게재되면 (주소 + 면적 + 간취り + 층)으로 접습니다. 남은 쪽에 `also:포털명` 태그가 붙습니다.
3. **차분** — 직전 스냅샷과 비교해 新着 / 価格変更 / 掲載終了를 뽑습니다. 포털이 push를 주지 않으므로 polling + diff 외의 방법이 없습니다.
4. **관측 로그** — 처음 본 가격과 바뀐 가격만 `observations.jsonl` 에 덧붙입니다. 같은 물건을 매일 다시 적으면 최근 분기 표본만 부풀어 추이가 휩니다.
5. **추이 집계** — 관측 로그에서 (구 × 단계 × 분기) 坪単価 중앙값을 냅니다. 표본이 `min_samples` 미만인 분기는 0으로 눕히지 않고 **결측으로 두고 선을 끊습니다.**

### 설정 (`config.json`)

| 키 | 뜻 |
|---|---|
| `trends.min_total_units` | 화면 기본 세대수 하한 (기본 500) |
| `trends.unit_thresholds` | 미리 계산해 둘 세대수 기준 목록 (기본 200/300/500) |
| `trends.min_samples` | 분기당 최소 표본. 미만이면 그 분기는 결측 |
| `trends.granularity` | `quarter` / `month` / `year` |
| `trends.wards` | 대상 구 코드 |
| `official_market.enabled` | 국토교통성 성약가 차트 사용 여부 |

### 운영 메모

- `observations.jsonl` 은 계속 누적됩니다. 실제 소스 연결 후에는 하루 수백 행 정도이며, 오래되면 분기 집계로 압축하는 편이 좋습니다.
- `web/data/changes/` 는 일별 차분 archive입니다. 사이트는 읽지 않으므로 `.gitignore` 처리되어 있습니다.

## 역세권 세분화와 지도

구 하나는 너무 넓습니다. 같은 新宿区라도 新宿駅 주변과 四ツ谷駅 주변은 다른 시장이라,
구를 다시 **역세권**으로 쪼갭니다 (7개 구, 44개 역).

- **지도** — 역 좌표에 점을 찍습니다. 색이 진할수록 비싸고(한 색상 밝음→어두움 램프),
  점이 클수록 표본이 많습니다. 점을 누르면 아래 매물 목록이 그 역세권으로 좁혀집니다.
- **역세권별 추이** — 역 단위는 표본이 적어 분기로 쪼개면 선이 끊깁니다. 그래서 **반기**로 묶습니다.

역 좌표는 `market.py` 의 `STATION_AREAS` 에 있습니다. **개략값**이며 측량값이 아닙니다.
정밀한 값이 필요하면 国土数値情報「鉄道」 데이터로 교체하세요.

세대수 기준을 500으로 올리면 실제로 해당하는 맨션이 많지 않아 지도에 점이 적게 찍힙니다.
그래서 200/300/500 세 기준을 미리 계산해 두고 화면에서 바꿀 수 있게 했습니다.

## 언어 전환

우측 상단에서 **한국어 / 日本語** 를 바꿀 수 있습니다. 선택은 브라우저에 저장되고,
처음 방문 시에는 브라우저 언어가 일본어면 일본어로 시작합니다.

UI 문구·구 이름·역 이름·단위는 번역되지만, **물건명과 노선명은 일본어 그대로** 둡니다 —
원본 데이터의 고유명사이고, 한국어 이용자도 실제 검색에는 그 표기를 쓰기 때문입니다.

## 사이트 화면

- **필터 한 줄** — 지역(7개 구) · 구분(중고/신축/둘 다) · 기간 · 실額↔지수. 아래 모든 차트에 같이 적용됩니다.
- **구별 坪単価 추이** — 구마다 색이 고정입니다. 필터로 계열이 줄어도 남은 구의 색은 바뀌지 않습니다.
- **구별 상세** — 구를 하나씩 떼어 중고(실선)와 신축 분양(파선)의 간격을 봅니다.
- **기간 변동률** — 선택 기간 동안 어느 구가 얼마나 올랐는지.
- **역세권 지도 / 역세권별 추이** — 위 참조.
- **신규 매물** — 최근 7일 신규 등록분. 지도에서 역을 고르면 그 역세권만 남습니다.
- **표로 보기** — 지도와 추이 모두, 모든 값을 색 없이 표로도 읽을 수 있습니다.
- 라이트/다크 모드 모두 대응하며, 계열 색은 색각 이상 조건에서의 구분도를 검증한 팔레트입니다.
